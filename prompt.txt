# SaaNgapi — Full-Stack Scheduling & Appointment Booking Architecture

A production-ready full-stack scheduling and appointment booking web application inspired by **Calendly** and **Cal.com**. It features dynamic timezone conversions, smart buffer management, atomic slot conflict prevention via database transactions, calendar `.ics` invite generation, and a responsive Tailwind CSS interface.

  id          String     @id @default(uuid())
  userId      String

  endTime     String     // "HH:mm" format, e.g. "17:00"

  @@index([userId, dayOfWeek])

## ⚡ 3. Core Slot Engine & Conflict Prevention

### Slot Generation & Overlap Logic ([`slotCalculator.ts`](file:///c:/Users/Eddy/Desktop/Projects-2/SaaNgapi/server/src/services/slotCalculator.ts#L22-L179))
The function [`calculateAvailableSlots`](file:///c:/Users/Eddy/Desktop/Projects-2/SaaNgapi/server/src/services/slotCalculator.ts#L22) operates as follows:
1. Determines day-of-week relative to the **host's native timezone**.
2. Checks for date-specific overrides ([`AvailabilityOverride`](file:///c:/Users/Eddy/Desktop/Projects-2/SaaNgapi/server/prisma/schema.prisma#L86)).
3. Reads recurring weekly working hours ([`Availability`](file:///c:/Users/Eddy/Desktop/Projects-2/SaaNgapi/server/prisma/schema.prisma#L70)) and converts them to UTC bounds via [`fromZonedTime`](file:///c:/Users/Eddy/Desktop/Projects-2/SaaNgapi/server/src/services/slotCalculator.ts#L80-L81).
4. Queries all existing active bookings within the window (`startTime < searchEnd && endTime > searchStart`).
5. Iterates candidate slots:
   - Evaluates buffer margins:
     $$\text{slotBufferStart} = \text{slotStart} - \text{bufferBefore}$$
     $$\text{slotBufferEnd} = \text{slotEnd} + \text{bufferAfter}$$
   - Evaluates overlap with existing bookings:
     $$\max(\text{candidateBufferStart}, \text{bookingBufferStart}) < \min(\text{candidateBufferEnd}, \text{bookingBufferEnd})$$
6. Discards past slots and slots violating minimum notice.
7. Translates approved UTC slots into both host and invitee local times using [`formatInTimeZone`](file:///c:/Users/Eddy/Desktop/Projects-2/SaaNgapi/server/src/services/slotCalculator.ts#L168-L169).

### Atomic Conflict Check & Booking Lock ([`public.controller.ts`](file:///c:/Users/Eddy/Desktop/Projects-2/SaaNgapi/server/src/controllers/public.controller.ts#L162-L260))
When an invitee confirms a slot, [`bookAppointment`](file:///c:/Users/Eddy/Desktop/Projects-2/SaaNgapi/server/src/controllers/public.controller.ts#L162) runs within a Prisma transaction:
```typescript
const booking = await prisma.$transaction(async (tx) => {
  const isFree = await verifySlotAvailability(
    tx,
    host.id,
    startTime,
    endTime,
    eventType.bufferBefore,
    eventType.bufferAfter
  );

  if (!isFree) {
    throw new Error('SLOT_CONFLICT');
  }

  return tx.booking.create({
    data: {
      eventTypeId: eventType.id,
      hostId: host.id,
      inviteeName,
      inviteeEmail: inviteeEmail.toLowerCase(),
      inviteeTimezone,
      inviteeNotes: inviteeNotes || null,
      startTime,
      endTime,
      status: 'CONFIRMED',
      meetingUrl
    },
    include: { eventType: true, host: true }
  });
});
```
If two invitees submit for the exact same slot concurrently, the transaction guarantees that the second attempt fails with an HTTP `409 Conflict`.
